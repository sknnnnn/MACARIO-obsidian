> Fecha: 2026-10-06.
>
> Fundación espacial aprobada a partir del frame de Figma **GXK 12:2 — SPACING & LAYOUT FOUNDATIONS V0.1** (Node `301:2348`).
>
> Jerarquía: **Brand & E-commerce Bible → Dirección Visual → V0.3 → Spacing & Layout → implementación.**

## Objetivo

Definir un sistema espacial finito y reutilizable para que las páginas GXK puedan implementarse sin inventar spacing estructural sección por sección.

Pregunta de validación:

> **¿Podemos construir el Home completo usando estas reglas sin inventar valores arbitrarios de spacing, gutters, gaps o dimensiones estructurales?**

**Sí.**

## 1. Escala

Escala base aprobada:

**0 · 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96 · 128**

Es una escala finita. No se agregan valores solamente para cubrir casos hipotéticos.

## 2. Contenedor y eje

Regla base:

**min(viewport − 2×gutter, 1312px)**

Gutters:

- Desktop: **64px**
- Tablet: **32px**
- Mobile: **20px**

El contenido utiliza un eje estructural único.

Las superficies pueden ser **full-bleed** y retornar al mismo eje; no se crean ejes alternativos por sección.

## 3. Grid

- Desktop: **12 columnas / gap 24px**
- Tablet: **8 columnas / gap 24px**
- Mobile: **4 columnas / gap 16px**

Los spans deben resolverse preferentemente con columnas enteras.

No crear grids alternativos sin una razón de diseño explícita.

## 4. Ritmo vertical

Tres familias conceptuales:

- **Compacta:** 48 / 40 / 32
- **Standard:** 80 / 64 / 48
- **Editorial:** 128 / 96 / 64

No son presets rígidos. Son referencias para expresar jerarquía entre elementos relacionados, grupos, bloques y secciones.

## 5. Relaciones internas

Patrones aprobados:

- Label → title: **8**
- Eyebrow → title: **12**
- Image → text: **16**
- Title → description: **8 / 8 / 8**
- Description → CTA: **24 / 24 / 24**
- Card content gap: **16 / 16 / 16**
- CTA de sección: **32 / 24 / 24**

Las diferencias entre Producto, Outfit, Editorial y Card contenida responden a función, no a una estética universal.

### Producto / Outfit

Padding global **0** como base; no imponer caja, borde o padding cuando el contenido no lo necesite.

### Editorial

Content gap de referencia: **24px**.

### Card contenida

Padding de referencia: **24 / 24 / 16**.

## 6. CTA

Especimen actual:

- Alto: **48px**
- Padding inline: **20px**
- Gap entre acciones: **12px**
- Touch target mínimo: **44px**

Regla de crecimiento:

**altura ≥ max(48, contenido + 24) px**

El 48/20 es referencia del espécimen, no una obligación de ancho fijo ni una dependencia de la tipografía incompleta.

## 7. Header

Regla espacial:

- Altura mínima: **80 / 64 / 64**
- Gutter: **64 / 32 / 20**
- Separación entre grupos: **32 / 24 / 16**
- Dentro de grupos: **16 / 12 / 12**
- Áreas de acción: **≥44px**

Esto define spacing, no rediseña el header.

## 8. Responsive

No existen tres sistemas independientes.

Las relaciones responsive deben resolver:

- mantener;
- reducir;
- reordenar;
- wrap;
- stack;
- full-width cuando corresponda.

Mobile no es una reducción mecánica del desktop.

## 9. Regla de implementación

Si una sección necesita un spacing que no puede resolverse con esta foundation:

> **No inventarlo silenciosamente. Reportarlo como excepción de diseño.**

Una excepción puede incorporarse al sistema solamente después de validación visual.

## 10. Validación GXK

La foundation debe servir a:

**CLARIDAD → IDENTIDAD → EXPLORACIÓN → EFECTO VISUAL**

y permitir:

**ESTRUCTURA → TENSIÓN → RUPTURA → RESOLUCIÓN**

El spacing aporta estructura y jerarquía. La ruptura visual no debe depender de márgenes arbitrarios.
